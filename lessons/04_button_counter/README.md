# 04 · Button counter

**Goal:** handle real-world inputs safely: synchronizers and edge detection.

Press **KEY0** to count up; press **KEY1** to reset. The count shows in hex on `HEX1:HEX0` and in
binary on the LEDs.

## Three ideas

1. **Synchronizer.** The button can change at any moment, even right as the clock ticks, which can
   leave a flip-flop in an undefined "metastable" state. Two flip-flops in a row give it time to
   settle. Do this for *every* input that isn't generated by your own clock.
2. **Edge detection.** A press lasts about 100 ms, which is 5 million clock cycles. Counting while
   the button is held would add millions. Instead, remember last cycle's value and act only on the
   change from released to pressed.
3. **Active-low.** `KEY` reads 0 while pressed, so the design inverts it.

The DE10-Lite's push buttons pass through a Schmitt trigger on the board, which cleans up contact
bounce. The slide switches don't have that, so they bounce (see exercise 3).

## Simulate

```bash
make sim
make wave    # look at KEY, key0_sync, press, and count
```

## Exercises

1. Remove the edge detector (count up whenever `key0_down` is 1). What happens on the board?
2. Make KEY1 count *down* instead of resetting.
3. Count flips of `SW[0]`. Does it sometimes count more than once? That's bounce. Write a
   debouncer: only accept a new value after it has been stable for ~10 ms (500,000 clocks).
4. Show the count in decimal (0–255) on three displays.
